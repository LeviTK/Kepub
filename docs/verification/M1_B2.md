## 已实现入口和政策

```sh
go build -o /tmp/kepub ./cmd/kepub
/tmp/kepub validate 'book.epub' --json
/tmp/kepub validate 'explicit publication root' --strict --timeout 30 --json
/tmp/kepub pack 'explicit publication root' --output 'new output.epub' --json
/tmp/kepub pack 'explicit publication root' --output 'draft.epub' --draft --json
```

`--output/-o` 必需；`--rootfile` 精确选择多 rootfile；选项可放目标前后；`--` 结束选项。
`--strict` 将 warning 纳入失败门槛；`--timeout` 为正整数秒。
JSON 成功/失败都只有一个 envelope。查询仍不需要 Java。validate 没有公开 `--draft`；pack 只有显式 `--draft` 才跳过 EPUBCheck，结果 `draft:true, verified:false`，检查状态 `incomplete`，绝不自动降级。

检查报告区分每层的 `required`、`coverage`、`status`、版本、规则、配置摘要和输入摘要：

| checker | 正式必需 | 状态与门槛 |
|---|---|---|
| archive | 是 | 有界安全 ZIP/目录快照及实际条目清单 |
| parse.structure | 是 | 选定 container/OPF 的可解析结构；保留既有 UTF-8/DTD/xml:base 等支持限制 |
| references | 否 | 原样保留逐语法 coverage；partial/blocked 不自行阻止无结构修改的打包；具体 error/fatal 仍阻止，strict 也阻止 warning |
| epubcheck | 是，草稿例外 | 固定工具、完整最终 ZIP 检查与报告证据；缺依赖 unavailable，异常 failed，草稿 not_run |
| rendering / accessibility | 否 | 显式 not_run；不把 conformance 当阅读器表现或人工可访问性审核 |

总体 `pass` 仅指请求的必需门槛全部通过；内容失败为 `fail`，缺依赖、超时、坏报告、输入漂移等为 `incomplete`。草稿永不标 pass。
严重结构失败时 references 为 blocked；安全导入失败时依赖层全部 blocked。严重诊断和依赖不可用可以同时保留，顶层错误按参数 → 冲突 → 依赖 → 执行/I/O → 内容优先。
rename 不属于本次实现，仍 planned；它以后仍须证明受影响引用覆盖充分。

## 冻结、清单和发布 API

依赖方向：`app → validation → archive/publication/references`，archive/validation 生产代码不 import workspace。
原有 `publication.Load/ReadXML` 的 `*archive.Archive` 接口未拆改；目录先成为独立私有 Archive 再使用这些读取器。

```go
archive.SnapshotDirectory(dir string, limits archive.Limits) (*archive.Archive, archive.Tree, error)
(*archive.Archive).Inventory() (archive.Tree, error)
(*archive.Archive).WriteZIP(w io.Writer, approved archive.Tree) error
(*archive.Archive).PublishZIP(ctx context.Context, output string, approved archive.Tree,
    check func(filename, archiveSHA256 string) error) (string, error)

validation.Validate(ctx context.Context, input string, o validation.Options) (validation.Report, error)
validation.CheckZIP(ctx context.Context, filename, expectedSHA256 string,
    o validation.Options) (validation.Report, error)

app.Pack(ctx context.Context, dir, output string, o validation.Options) (app.PackResult, error)
app.PackSnapshot(ctx context.Context, a *archive.Archive, approved archive.Tree,
    output string, o validation.Options) (app.PackResult, error)
```

Options：`Rootfile string`、`Strict/Draft bool`、`Timeout time.Duration`（0 为默认 120 秒 EPUBCheck 限额）、`Java/JAR string`（可信调用者配置；不从书籍内容读取）。CLI 的显式 timeout 还覆盖请求上下文。
后续 workspace export 应调用 **PackSnapshot**，不能直接把低层 WriteZIP/自定义 PublishZIP 回调产物标成正式验证通过。

`archive.Entry/Tree` 与现有 workspace 同字段、同摘要契约：完整文件和目录条目（含空目录），按精确 Path 排序，JSON 编码 Entries；SHA-256 输入为 `kepub-tree-v1\n` 加 JSON 字节。
`inputTreeSha256` 不等于 `archiveSha256`。测试用 workspace.HashTree 独立核对二者实现相容；无需 workspace 生产依赖。
已批准清单与冻结内容不符（额外/遗漏条目、内容漂移、伪造摘要）拒绝；低层 ZIP writer 只迭代清单，不扫描整个 workspace。
公开 pack 将显式 DIR 全部安全资源作为出版清单，不发现上级工具文件；因此 DIR 必须是 `pub/`，不是整个工作区。未知原有资源和空目录保留，不按文件名黑名单删除。

目录快照拒绝 symlink/hardlink/特殊文件、非规范路径、大小写/Unicode 碰撞及超限；`os.Root` 限制路径解析，文件 no-follow/nonblocking，并前后比较内容清单。调用者仍须先停止外部写者，目录 walk 不是原子文件系统快照或同用户 OS 沙箱。
应用自己新建的私有 staging 路径单独 canonicalize，允许系统 TMPDIR 的正常别名；已先复现 TMPDIR symlink 导致 Inventory 误拒绝，再用回归测试修复。没有因此允许出版根或输出父目录中的链接；这仍不是 Mac 实机证据。
默认限额：20,000 条目、256MiB/文件、2GiB 总展开量；validate 还限制压缩输入为 2GiB。沿用 BookPath/XML 限额。

输出必须不存在且在 publication root 外，父目录必须已存在且没有 symlink。
同输出目录 0600 临时归档 → 独立安全重新导入及完整树比对 → 最终归档检查 → 前后 SHA-256 复核 → 平台原子 no-replace 发布。
检查失败、超时、漂移均不发布；并发两个 publisher 只有一个成功；不能覆盖原书或既有路径。正常失败清理临时文件，突然终止仍可能留临时产物；不宣称断电耐久性。
`mimetype` 使用 CreateRaw：第一 local/central entry、STORE、精确 `application/epub+zip`、无 extra、无 data descriptor、无加密；有二进制 header 回归测试。重打包保留出版资源原字节，不承诺原 ZIP 压缩字节相同。

```sh
  -o /tmp/kepub-tools/epubcheck.zip
printf '%s  %s\n' \
  6c07e68584b2e2ce2f89fe06e1246dfead3eb36b46b340e7d93524f29dcff6c5 \
  /tmp/kepub-tools/epubcheck.zip | sha256sum -c -
```

Java 安装包非项目 pin，平台安装由集成线程另行协调；上面的 apt 操作只能复现安装方法，不保证未来仓库仍提供同一 Java 包。

- 发行 ZIP SHA-256：`6c07e68584b2e2ce2f89fe06e1246dfead3eb36b46b340e7d93524f29dcff6c5`
- epubcheck.jar SHA-256：`f7f96617c929371821609b88c8484d6dc9f24fe916499863c46094c5fb778a65`
- 完整 executable JAR 集摘要：`158b7c2778c3b64d5dbd87151b7d1f870b03beda3bee973d52b3fe58bea16266`

最后一项是对 epubcheck.jar 与 lib/*.jar 的 `relative/path:sha256\n` 行按路径排序后的 SHA-256；适配前后核对此值。
只伪造 `--version` 或替换依赖 JAR 不够。非官方打包/Maven 单 JAR/其他版本明确 unavailable，不盲用。
完整工具摘要可在解压目录以如下命令独立核对：

```sh
(for f in epubcheck.jar lib/*.jar; do

```

实际 argv（参数数组，绝对路径，不经 shell）：

```sh
java -Xmx512m -Depubcheck.offline=true \
  -Djavax.xml.accessExternalDTD= -Djavax.xml.accessExternalSchema= \
  -Djavax.xml.accessExternalStylesheet= \
  -jar "$KEPUB_EPUBCHECK_JAR" --json - --quiet --locale en /absolute/private/input.epub
# strict 额外追加 --failonwarnings
```

不传单文件 `--mode`、远程 input URL、message override 或自定义 schemas。剥离 JAVA_TOOL_OPTIONS/JDK_JAVA_OPTIONS/_JAVA_OPTIONS/CLASSPATH 注入。
stdout/stderr 各限 16MiB；超限取消进程组，不写无界外部报告文件；JVM heap 限 512MiB；timeout/SIGINT 终止整个受管进程组。
SIGINT CLI 在检查期间返回 130 单 envelope，未发布。POSIX 进程组不是任意脱组恶意进程回收保证。

EPUBCheck 5.3.0 JSON 无可靠 completed 字段；异常路径可能生成部分报告，`nError==0` 不能表示完整。
通过须同时满足：成功退出、无超时/输出溢出、一个合法无重复键/不过深 JSON、准确 checkerVersion、完整 counts/messages、publication 规则和基本字段、全部非目录 item 的路径/size/checksum 与独立安全库存匹配，以及过程前后输入和工具 hash 一致。
5.3.0 checksum 是逐字节**无零填充 hex**，已按固定上游格式比较，不能把它误当标准 64 字符 hex。
非零退出永远不 pass；有可读内容诊断可返回 fail，但不据此声称异常报告完整；零错误的非零退出是执行失败。
保留 rawReport（或 invalidReport 原文）、backendExitCode、upstreamCode、checker reason 与可得位置；不可得行列为 null。原始报告保留操作路径，不是自动脱敏分享包。

上游正常 packaged 路径使用本地 ZIP/classpath schemas，外部实体禁用；此外设置 offline/JAXP 外部访问属性。真实 EPUB2/3 外部 HTTP/file entity fixture 没有触发测试 HTTP 服务，未扩展外部文件 sentinel。
这不是 OS 网络/文件系统沙箱：上游某些 resolver 有 fallback，Java/runtime 必须可信；没有证明被替换运行时或同 UID 攻击者无法联网/读取外部文件。来源：[XMLParser](https://github.com/w3c/epubcheck/blob/v5.3.0/src/main/java/com/adobe/epubcheck/xml/XMLParser.java)、[DefaultResolver](https://github.com/w3c/epubcheck/blob/v5.3.0/src/main/java/com/adobe/epubcheck/xml/handlers/DefaultResolver.java)。


## 首次交付后的两项增量修复

增量基线为本地交付提交 `6853b517518b551c87e5bdf7caf242dbb93246fb`。只修复 root 退出后残余受管写者和原子发布取消语义。

真实复现：root 正常 exit 0/非零 exit 7 并关闭后代 stdout/stderr 时，原实现 terminal 后分别残留 S/R 状态成员并发生迟延写；继承管道触发 WaitDelay 时也留下 S 状态成员并迟延写。首次 timeout 测试不能证明这些边界安全。
现在 cmd.Run 返回后独立检查组存在性：发现残余组即 SIGKILL 并有界核查没有活成员，正常 root 留残余组也返回执行失败，不能因 exit 0/完整 JSON 变成 pass。Linux 只在 SIGKILL 后排除 Z/X，并处理 stat 消失的 ENOENT/ESRCH；Darwin 保守要求组 ESRCH。清理检查最多 2 秒，失败仍 fail-closed；没有 subreaper 或脱组回收保证。

新增 `TestProcessRootExitReclaimsWriters` 三个边界均有真正迟延写正对照（1.6 秒后写 `unsafe`），修复后 terminal 无活 PGID 成员、1.8 秒后无迟延写。定向 race（含既有 timeout、发布前取消和 CLI 提交语义）全部通过，validation 14.089s。

PublishZIP 的唯一 API 变化是增加首参数 `ctx context.Context`，app.PackSnapshot 已传递原请求 context。最终重新 hash 完成后、紧接原子 no-replace 调用前观察 ctx.Err；已知取消返回 `PUBLICATION_CANCELLED`，清理 staging，不发布。成功原子发布是提交点，返回真实 archive hash，之后取消不再改写成功结果。CLI 只把尚未成功且 context cancelled 的请求映射为 130；deadline 发布前取消为 exit 5。没有承诺赢过最后 context 观察与 rename 同时到达的信号。

回归区分：检查回调取消后仍返回 nil → 最终 hash 之后取消门槛拒绝发布且不漏 staging；CLI 提交前已取消 → 130 且无产物；通过真实 Pack、输出存在后在下次 Err 观察注入取消 → 仍成功并保留输出/hash。后一测试可以直接发现旧 CLI 的无条件取消改报逻辑；不靠信号/rename 的竞速概率。
